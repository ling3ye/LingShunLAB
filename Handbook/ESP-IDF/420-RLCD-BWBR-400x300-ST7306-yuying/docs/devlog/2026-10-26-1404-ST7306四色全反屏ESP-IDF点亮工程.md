## 关于接线

这个模块接线不用驱动电路，只要一个转接板接上FPC就可以直接GPIO驱动屏幕，当然会建议在靠近屏幕电源端增加去藕电容电路，增加其稳定性。

 * 接线（与 bringup 工程 / 黑白版一致，新板引脚）：
 *   LCD_CS   = GPIO9
 *   LCD_RST  = GPIO10   
 *   LCD_TE   = GPIO11   （本示例不读 TE，留空亦可）
 *   LCD_SCLK = GPIO12
 *   LCD_MOSI = GPIO13   （即 SDI ）
 *   LCD_RS   = GPIO14   （即 LCD_D/C ）
 *   VCI      = 3.3V
 *   GND      = GND

> 如果使用的是厂家那块有2个FPC接口的通用，则需要注意：
>
> - 接线板上的「RS」对应的是 LCD_D/C 接 GPIO14 ,而并非接线板上的「DC」，接线板上的「DC」与这个模块无关。
> - 接线板上「RESET」对应的是 LCD_RST ,接 GPIO10 。
> - 「TE」对应的是 LCD_TE ，因为本例子中没有使用到到，所以可以不接。

## 开发记录

### 驱动层（`main/st7306_color4.h` / `.cpp`）

从 bringup 工程的 `st7306_color4.cc` 移植，初始化序列（D6/D1/C0/C1/C2/C4/C5/D8/B2/B3/B4/62/B7/B0/36/3A/B9/B8…）与显存排布一字未改，只做两件事：

- 把 C++ 类包一层 `extern "C"` 的 handle 接口（`st7306_init/write_point/display/fill_rect/…`），让上层 demo 全部用 C 写，与黑白版 `lcd_demo.c` 的写法保持一致，便于逐页对照。
- 新增 `st7306_fill_rect()`：按 2×2 像素块直写显存，整块同色时一次按平面掩码置位，边界奇数列/奇数行退回逐点写。实测比逐点快约 4 倍，动画页才跑得动。

显存基本事实（本轮确认）：300×400、2bit/像素、每行 150 字节、上下两行合成一行数据、共 200 数据行 = **30000 字节**（黑白屏是 15000）。颜色编码 `bit0=青 / bit1=红 / 双位=黑`，即 `WHITE=0x00 CYAN=0x01 RED=0x02 BLACK=0x03`。

### 绘制层（`main/st73xx_ui.h` / `.c`）

函数名与黑白版的 `st73xx_ui.h` 完全对齐（`ui_draw_line/rectangle/filled_circle/filled_triangle/filled_polygon/…`），这样两个工程的页面代码可以并排阅读。内部全部走 `fill_rect`/`write_point`，整型 Bresenham，无浮点依赖（三角形扫描线填充除外，那里用了 float 求插值）。

### 演示层（`main/color4_demo.h` / `.c`，1297 行）

- **第 1–15 页逐页复刻黑白版**：页面顺序、版式坐标、驻留时长、帧率上限全部照搬 `lcd_demo.c` 的 `pages[]` 表（3500/6500/5000/5000/5500/9000/8500/6000/9000/9000/12000/9000/6500/6000/12000 ms）。
- 对齐的关键手法：黑白版靠 4×4 Bayer 抖动伪造 17 级灰阶，四色屏没有中间调。代码里**保留 `gray_rect()` / `gray_circle()` 同名函数**，内部改成画青色实心块，于是页面主体代码与黑白版仍是一一对应；第 2 页专门把 17 级灰量化成 白→青→红→黑 四档，直观展示这个压缩过程。
- 单色页上的重点元素用红/青做语义色：电量条按阈值变色、近处星星用红、生命游戏前 8 代用红、时钟秒针红分针黑、警示条红底白字。
- **第 16–20 页为四色专属**：Color cycle（整屏四色轮播）、Color card（色卡 + 2bit 编码说明）、Quad split（同一图形四组配色比可读性）、HMI demo（红色警示条 / 状态灯 / 青色进度条）、Color flow（四条流动彩带）。
- 页码与进度点由轮播器统一设置 `g_page_index` 驱动，不在各页硬编码，20 页时进度点间距自适应压缩到 3px。

## 验证过程与发现的问题

在主机端把 `color4_demo.c` 整体 include 进一个测试程序，用 stub 头文件替换 FreeRTOS/SPI/日志，保留真实绘制代码，把 20 页渲染成 300×400 图像逐页目视检查。这一步查出四类问题，全部已修：

1. **`fill()` 位平面展开错误（真 bug）**。原实现按 `c | c<<2 | c<<4 | c<<6` 把 2bit 颜色铺满一字节，但两个 bit 平面是交错排布的（bit7/6/3/2 = bit1 平面，bit5/4/1/0 = bit0 平面）。结果填白填黑碰巧正确，**填青得 0x55（应 0x33）、填红得 0xAA（应 0xCC）**。改为按平面掩码累加：`bit1 → |=0xCC`、`bit0 → |=0x33`。修完用逐点写全屏填充作基准逐字节比对，四种颜色 0 失配。
2. **旋转页 90°/270° 映射方向错、圆画成椭圆**。初版用 12 点查表近似圆，逻辑空间里就不是正圆；`MAP_Y` 在 90°/270° 的分支也写反了。改为整数牛顿迭代开方逐行解 `x=sqrt(r²−y²)` 画正圆，并修正映射：`0°:(lx,ly)`、`90°:(W−1−ly, lx)`、`180°:(W−1−lx, H−1−ly)`、`270°:(ly, H−1−lx)`。四个相位逐个渲染确认标题栏位置、箭头方向、正圆度均正确。
3. **`fill_rect` 与逐点写一致性**：300 组随机矩形（含越界坐标）双路绘制后 memcmp，**0 差异**。
4. **三处版式问题**：色卡页底部文字压页脚线、Quad split 说明文字压页脚栏、Color flow 彩带遮挡文字块。分别抬高文字 / 收窄色块 / 把彩带与文字分到上下半屏。

ESP-IDF 侧：v6.0.2 / 目标 esp32s3，`idf.py build` **零警告**通过，bin 0x3a830 字节，app 分区剩余 77%。期间只遇到一次编译错误——`std::nothrow` 缺 `<new>`，补头文件即解决。
